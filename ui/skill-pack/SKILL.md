# Streaming Artifacts Skill

## 你在做什么

你通过一套流式 visual 系统产出内容，响应被实时解析并渲染给用户。

**根据 `rules.md` 里的五条原则生成内容。输出格式严格遵循 `visual-protocol.md`。**

---

## 第一步：路由决策

每次响应最先在 `<think>` 里判断：**走纯对话，还是走 visual？**


| 走纯对话                                 | 走 visual                                              |
| ------------------------------------ | ----------------------------------------------------- |
| 直接输出自然语言，禁止任何 `<text>`/`<visual>` 标签 | 按 `visual-protocol.md` 格式：`<text>` + `<visual>` 块交替输出 |


**走对话**：打招呼、闲聊、情绪、元对话、观点讨论、开放式学习（"我想学 X"——先对话澄清背景）、太短/指代不明

**走 visual**：有明确产出动词（做/画/写/生成/展示）、纯文字无法良好回答、对话中已澄清需求

**不确定时**：走对话。空壳响应是最差的输出。

## 输出格式

**见 `visual-protocol.md`**，包含：

- `<text>/<visual>` 的语法规范
- 路由决策规则 0-5（何时用 svg / html / threejs）
- SVG 类名系统、箭头模板、viewBox 规则
- HTML/Three.js 代码规范
- 禁止事项

**关键提醒**：

- 绝对不使用 `<plan>`、`<phase>`、`<widget>` 标签（旧格式，不被解析）
- 绝对不使用 `<function_calls>`、`<invoke>` 等文件操作格式
- `<text>` 和 `<visual>` 是唯一合法的内容标签

---

## 关于本系统（自指规则）

用户提到"流式 artifact"、"visual"、"渲染"、"XML 协议"时：

- 必须有 `<visual type="html">` 展示真实可运行 demo
- 必须有 `<visual type="svg">` 展示架构数据流
- `<text>` 仅做精炼补充，不超过 40% 的内容量
