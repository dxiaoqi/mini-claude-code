# Consulting Recipe（参考示范，不是模板）

> v5 说明：不要"识别为 Self/Mixed → 套 consulting 模板"。这个文件是**参考示范**，
> 展示当用户提到自身状态或困扰时高质量产出是什么样的。看模式，不要复制结构。

## 何时用

用户请求类型为 **Self / Pain / Mixed** 时使用。**纯 Topic 请求不用此 recipe。**

| 类型 | 信号 | 区分方法 |
|---|---|---|
| Self | "我的思维"、"我希望改变"、"我太X"、"我不够Y"、"帮我培养" | 用户在做自我评价 |
| Pain | "我遇到"、"我没法"、"总是被"、"怎么解决" | 用户描述了具体负面体验 |
| Mixed | Self/Pain 信号 + "我想学X" | 用户说了"我[困扰] + 想学X" |

**不要混淆**：
- "什么是 X" → 纯 Topic，不用 consulting
- "我总是 Y，什么是 X" → Mixed → consulting

**Mixed 的主层判断**：self > pain > topic，找出用户真正想解决的是什么。

## 平庸产出 vs 高质量产出（必须模仿高质量）

### 用户问："我思维线性，想学产品管理"

**意图识别**：Mixed = Self（线性思维）+ Topic（产品管理），Self 主导

---

#### ❌ 平庸产出（要避免）

```
P1: SVG 产品管理核心循环（讲 PM 的工作生命周期）
P2: 非线性问题发现框架（三阶段方法论：发散→收敛→决策）
P3: 用户访谈模拟器（教怎么做用户访谈）
```

**为什么平庸**：
- Topic 副层（产品管理）被当成了主角
- Self 层（"我的思维线性"）被完全忽略，用户的"我"没被看见
- 用户读完是"我学了一点 PM 知识"，不是"我理解了自己的思维模式"
- P3 是用户访谈教学，和"线性思维"的连接完全切断了

---

#### ✅ 高质量产出（要模仿）

```xml
<think>
Mixed 请求。识别为 Self 主导（线性思维），依据是用户原话"我思维线性"。
产品管理是副层工具，不是主题。

P1 直接切入线性/非线性思维的对比，让用户识别自己的模式——不讲 PM 通识
P2 可操作的练习器，让用户感受到思维方式的实际差异——PM 方法（如 5 Why）作为练习工具
P3 长期工具，具体到"在什么场景下用什么替代什么"——用户可带走

独特价值：P1 有两种思维的并排对比；P2 有用户自己操作的练习；P3 有具体到今天就能做的动作。
</think>

<plan recipe="consulting" depth="standard">
  <phase id="p1" goal="用 SVG 对比图展示线性/非线性思维者面对同一个用户反馈的不同解读路径，让用户对照自己属于哪种">
    <acceptance>
      <criterion type="widget_exists" widget="svg"/>
      <criterion type="semantic" desc="对比具体到行为层面，用户能对号入座"/>
    </acceptance>
  </phase>
  <phase id="p2" goal="用 html 练习器：给用户一段用户反馈原话，让用户练习追问 3 层，系统给出'更接近线性/非线性'的判断和原因">
    <acceptance>
      <criterion type="widget_exists" widget="html"/>
      <criterion type="semantic" desc="用户做完后能感受到自己思维方式的特点"/>
    </acceptance>
  </phase>
  <phase id="p3" goal="交付'每周可练习的非线性思维微动作'：3个具体到今天就能做的场景替换，PM 方法论作为动作的实现工具引用">
    <acceptance>
      <criterion type="semantic" desc="每个动作具体到'在什么场景下，用什么替代什么'"/>
    </acceptance>
  </phase>
</plan>
```

**执行后的 Phase 内容要点**：

**P1 SVG**：两列对比图，同一个用户说"这个功能不好用"：
- 左列（线性）：收集反馈 → 改功能 → 上线
- 右列（非线性）：追问"不好用"的具体场景 → 识别是功能问题还是工作流问题 → 发现真正要改的是流程

SVG 去掉文字后，两条路径的分叉点仍然可见 ✓

**P2 HTML**：练习器不是"看对比演示"，而是用户自己操作：
- 系统给出用户原话（如"这个流程太复杂了"）
- 用户写出自己的第一反应
- 系统判断：这个反应是在"解决表述的问题"还是在"追问背后的问题"
- 反馈具体：如"你的反应是简化流程，这是线性思维——你接受了用户对问题的定义。非线性思维者会先问：他说的'复杂'具体指哪一步？"

**P3 Markdown**：不是"培养同理心"类泛泛建议：
- 具体到场景：在下次需求评审前，把每个需求单里的第一个词（通常是"增加/支持/做"）划掉，改写成"让用户能…"
- 用 PM 方法论作为工具：5 Why 在这里是"帮你实施追问的具体方法"，不是"方法论学习材料"

## 高质量 Consulting Phase 的模板

### Phase 1（诊断/对比展示）

```xml
<phase id="p1" goal="用 SVG/html 展示[用户描述的X状态]的具体表现形态，让用户对照识别自己">
  <acceptance>
    <criterion type="widget_exists" widget="svg"/>  <!-- 或 html -->
    <criterion type="semantic" desc="有可对号入座的具体场景，不是抽象定义"/>
  </acceptance>
</phase>
```

**必须做到**：用户看完后能说出"这个更像我"而不只是"原来有这几种类型"

### Phase 2（核心练习）

```xml
<phase id="p2" goal="用 html 练习器让用户操作一次[具体任务]，系统给出针对性反馈">
  <acceptance>
    <criterion type="widget_exists" widget="html"/>
    <criterion type="semantic" desc="用户做完后能感受到自己的思维方式特点"/>
  </acceptance>
</phase>
```

**必须做到**：用户操作 → 系统反馈 → 用户对自己的认知变深了

### Phase 3（可带走工具）

```xml
<phase id="p3" goal="交付[X具体动作]：3个具体到今天就能做的场景替换，含每步怎么操作">
  <acceptance>
    <criterion type="semantic" desc="每个动作具体到'在什么场景下，用什么替代什么'"/>
  </acceptance>
</phase>
```

**必须做到**：用户可以在下次工作中直接用，不需要先"理解框架"

## 引用用户原话（Pain/Self 请求强制）

产出里至少有一处精确引用用户原话：

- ✅ "你说'思维有些线性'，这个'线性'具体可能指两种情况..."
- ✅ "你提到'难以发现问题'，这个发现不了可能卡在几个不同的地方..."
- ❌ "很多人都有这个问题，让我们来看看..."（复述后给通用方案）

做不到精确引用 → 说明没有真正在处理这个用户的具体请求。
